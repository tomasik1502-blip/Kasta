# Фид CRM → Kasta (автообновление каждый час)

Скрипт каждый час забирает выгрузку товаров из CRM HugeProfit, приводит её к требованиям Kasta HUB
и публикует по постоянной ссылке:

```
https://<ваш-логин>.github.io/<имя-репозитория>/feed.xml
```

Эту ссылку один раз указываете в Kasta HUB, дальше цены, остатки и новые товары подтягиваются сами.

---

## Настройка (один раз, ~15 минут)

### 1. Создайте репозиторий
1. Зарегистрируйтесь на [github.com](https://github.com) (бесплатно), если аккаунта нет.
2. Справа вверху **+ → New repository**.
   - Repository name: например `kasta-feed`
   - Видимость: **Public** (бесплатный GitHub Pages работает только с публичными репозиториями;
     сам фид всё равно должен быть публичным, чтобы Kasta его забирала).
   - **Create repository**.

### 2. Загрузите файлы
На странице репозитория: **Add file → Upload files** → перетащите **содержимое** распакованного архива:
`crm_to_kasta.py`, `README.md` и папку `.github`.

> Папка `.github` скрытая. На Mac покажите скрытые файлы: Cmd+Shift+. ; в Windows: Проводник → Вид → Скрытые элементы.
> Без этой папки автозапуск не заработает.

Нажмите **Commit changes**.

### 3. Добавьте ссылку на CRM как секрет
Ссылка на выгрузку CRM содержит идентификаторы вашего аккаунта, поэтому она хранится в секрете, а не в коде.

**Settings → Secrets and variables → Actions → New repository secret**
- Name: `CRM_FEED_URL`
- Secret: `https://crm.h-profit.com/bremote-csv/get_xml_products?uid=4640&mid=5541&xml_type=rozetka`

### 4. Первый запуск
**Actions** → (если попросит) **I understand my workflows, go ahead and enable them** →
слева **Kasta feed** → **Run workflow** → **Run workflow**.

Через 1–2 минуты запуск должен стать зелёным. Появится ветка `gh-pages` с файлом `feed.xml`.

### 5. Включите GitHub Pages
**Settings → Pages** → Source: **Deploy from a branch** → Branch: **gh-pages**, папка **/ (root)** → **Save**.

Через пару минут фид откроется по адресу `https://<логин>.github.io/<репозиторий>/feed.xml`.

### 6. Подключите фид в Kasta HUB
**Товари → Імпорт новинок → XML → Додати новий фід** → вставьте ссылку из шага 5.

Рекомендуемые галочки на старте:

| Галочка | Значение | Почему |
|---|---|---|
| Завантажити товари з xml | ✅ | включает фид |
| Використати offer id, якщо немає артикула | ❌ | артикулы скрипт уже проставил; иначе варианты не склеятся |
| Використати ціну продажу, якщо немає рекомендованої ціни | ✅ | страховка |
| Зняти з продажу товари, які відсутні в фіді | ❌ на старте | включайте после первой успешной модерации |
| Оновлювати ціни / стоки / контент | ✅ | автообновление |

После первой загрузки скачайте в HUB «Файл ручного мапінгу» и заполните категории и бренды
(черновик — во вкладках файла `kasta_report.xlsx`).

## Как это работает

```
каждый час (:07 UTC)
  CRM (секрет CRM_FEED_URL)
    → crm_to_kasta.py  (чистка, склейка, категории, исключения)
    → проверка-защита
    → ветка gh-pages / feed.xml  →  Kasta забирает по ссылке
```

**Защита от пустого фида.** Если CRM недоступна, вернула битый файл или товаров стало меньше 70%
от прошлого раза, публикация отменяется и по ссылке остаётся предыдущий фид. Иначе при включённой
галочке «Зняти з продажу…» Kasta сняла бы товары с продажи. GitHub пришлёт письмо об ошибке запуска.

Если сокращение ассортимента плановое: **Actions → Kasta feed → Run workflow → отметьте force → Run**.

**Отчёт** по каждому запуску (исключённые товары и предупреждения) лежит в карточке запуска:
Actions → нужный запуск → Artifacts → `report`.

## Как поменять правила
Все настройки — в начале `crm_to_kasta.py`, блок `НАСТРОЙКИ`. Редактировать можно прямо на GitHub
(иконка карандаша на файле → Commit changes); следующий запуск применит изменения.

- `PRICE_MODE = 'online'` — продавать по цене «Онлайн» с перечёркнутой основной ценой.
- `SEND_PROMO = True` — передавать цену «Акция» (только после согласования акции с менеджером Kasta).
- `BRAND_MAP` — замена брендов.
- `EXCLUDE_REPLICAS = False` — не исключать товары с люксовыми брендами.
- `SPLIT_RULES` — разделение категорий. **Новые правила добавляйте в конец списка категории**:
  ID подкатегорий зависят от порядка правил, а на них завязан маппинг в HUB.

## Ограничения
- Расписание GitHub не точное: запуск может задержаться на 5–30 минут в часы пиковой нагрузки.
- В публичных репозиториях GitHub отключает расписание, если в репозитории 60 дней нет активности,
  и заранее присылает письмо. Включается обратно одной кнопкой в Actions.
- Не меняйте в CRM артикулы, бренды, цвета и размеры уже опубликованных товаров: Kasta воспримет
  такой товар как новый и отправит на повторную модерацию.
